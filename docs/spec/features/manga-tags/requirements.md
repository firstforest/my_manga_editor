## 概要

作品 (`Manga`) に自由入力のタグを複数付けられるようにし、作品一覧のカンバン (`/manga`) を
タグで絞り込めるようにする機能。

作品が増えるとカンバンは全作品がフラットに並ぶため目的の作品を探しにくい。
最も強い要望は「連載の各話をシリーズとしてまとめたい」だが、
**シリーズ専用の仕組みを作らずタグ 1 本で実現する**。
`連載:ヒーロー` のようなタグを各話に付ければシリーズになり、
`商業` `依頼` `没ネタ` のような分類にも同じ仕組みがそのまま使える。

タグは名前だけを持つ文字列で、独立したエンティティにはしない。
「存在するタグの一覧」は全作品のタグを重複除去して導出する。

---

## ユーザーストーリー

### US-1: 作品にタグを付けたい (priority: P1)

As a 漫画家（ユーザー），
I want 作品にタグを複数付けたり外したりでき，
so that 連載のまとまりや作品の性格（商業／同人／没ネタ など）を自分の分類で管理したい。

#### Acceptance Criteria

- AC-1.1: THE SYSTEM SHALL 各作品に **0 個以上のタグ（文字列の並び）** を持たせ、
  編集画面 (`/manga/:mangaId`) に現在のタグを一覧表示する
- AC-1.2: WHEN ユーザーがタグを入力して確定した
  THE SYSTEM SHALL 前後の空白を除去した文字列をその作品のタグとして追加し、追加した順に末尾へ並べる
- AC-1.3: WHEN ユーザーがタグの削除操作（タグ横の × ）を行った
  THE SYSTEM SHALL そのタグだけをその作品から外し、他の作品のタグには影響を与えない
- AC-1.4: IF 追加しようとしたタグが trim 後に空文字である
  THEN THE SYSTEM SHALL 追加せず、入力欄を閉じる（エラーは出さない）
- AC-1.5: IF 追加しようとしたタグが既にその作品に付いている
  THEN THE SYSTEM SHALL 重複して追加せず、入力欄をそのまま閉じる（エラーは出さない）
- AC-1.6: IF タグが trim 後に 30 文字を超える
  THEN THE SYSTEM SHALL 追加せず `タグは30文字以内で入力してください` の SnackBar を表示する
- AC-1.7: IF その作品のタグが既に 20 個ある
  THEN THE SYSTEM SHALL 追加せず `タグは1作品につき20個までです` の SnackBar を表示する
- AC-1.8: WHILE ユーザーがタグを入力している
  THE SYSTEM SHALL 既存のタグのうち入力文字列を含むものを候補として提示し、
  選択すればその名前がそのまま入力される（表記ゆれによるタグ分裂を防ぐため）
- AC-1.9: WHEN タグが追加・削除された
  THE SYSTEM SHALL 同じ利用者の他の開いている画面（カンバンの絞り込み候補を含む）へ
  Firestore の snapshot 経由でその変更を反映する

#### Edge Cases
- 前後の空白のみを入力 → trim の結果が空文字なので追加しない (AC-1.4)
- 既存タグと大文字小文字だけが違う文字列 → **別のタグとして扱う**（完全一致で判定する）
- 全角／半角の違い、旧字体などの表記ゆれ → 別タグ扱い。AC-1.8 の候補提示で予防する
- オフライン中の追加・削除 → Firestore キャッシュに書き込まれ、再接続時に同期される
- 2 端末で同じ作品に別のタグを同時追加 → 配列への追加操作なので両方が残る（後勝ちで消えない）
- 作品を削除した結果、あるタグが付いた作品が 0 件になる → そのタグは候補から自然に消える

### US-2: 一覧をタグで絞り込みたい (priority: P1)

As a 漫画家，
I want 作品一覧のカンバンを特定のタグだけに絞り込み，
so that 連載1本分の進行状況（アイデア／制作中／完成）だけを見たい。

#### Acceptance Criteria

- AC-2.1: THE SYSTEM SHALL 作品一覧 (`/manga`) のカンバンの上部に、
  `すべて` / `タグなし` / 存在する各タグ を選べる絞り込み UI を表示する
- AC-2.2: THE SYSTEM SHALL 絞り込みの選択肢のうちタグの一覧を、
  利用者が持つ全作品のタグから重複を除いて文字列の昇順に並べたものとする
- AC-2.3: WHEN ユーザーが特定のタグを選択した
  THE SYSTEM SHALL カンバンの3列 (アイデア／制作中／完成) に、そのタグを持つ作品だけを表示する
- AC-2.4: WHEN ユーザーが `タグなし` を選択した
  THE SYSTEM SHALL タグが 1 つも付いていない作品だけを表示する
- AC-2.5: WHILE いずれかのタグで絞り込まれている
  THE SYSTEM SHALL 各列のカード枚数バッジを**絞り込み後の件数**で表示する
- AC-2.6: WHILE いずれかのタグで絞り込まれている, WHEN ユーザーが「新規作成」を押下した
  THE SYSTEM SHALL 選択中のタグを付けた作品を作成する
  (`すべて` / `タグなし` 選択時はタグ無しの作品を作成する)
- AC-2.7: WHILE いずれかのタグで絞り込まれている
  THE SYSTEM SHALL カードのドラッグ&ドロップによるステータス変更を従来どおり許可し、
  ドロップ後もタグを変更しない
- AC-2.8: IF 絞り込み中のタグを持つ作品が 0 件になった
  THEN THE SYSTEM SHALL 絞り込みを `すべて` に戻す（存在しないタグで空の画面に取り残さない）
- AC-2.9: THE SYSTEM SHALL 絞り込みの選択をアプリ起動中のみ保持し、
  再読み込み後は `すべて` から始める
- AC-2.10: THE SYSTEM SHALL カンバンの各カードに、その作品のタグを先頭から最大 3 個表示し、
  4 個目以降がある場合は `+N` の形で残り件数を示す

#### Edge Cases
- 1つもタグが存在しない → 絞り込み UI は `すべて` / `タグなし` のみを出す
- 全作品がタグ無し → `すべて` と `タグなし` の表示内容が一致する（許容）
- タグ数が多い (20 件以上) → 絞り込み UI は横スクロールし、カンバンの高さを圧迫しない
- 絞り込み中に他端末で作品のタグが変わった → snapshot 反映で当該カードが列から消える／現れる
- 複数タグを持つ作品 → 該当するどのタグで絞り込んでも表示される

## 機能要件 (Functional Requirements)

- FR-001: THE SYSTEM SHALL タグを独立した Firestore ドキュメントとして持たず、
  作品ドキュメントの配列フィールドとして保持する
- FR-002: THE SYSTEM SHALL タグの同一性を **trim 後の完全一致**で判定する
- FR-003: THE SYSTEM SHALL 1 作品の中でタグを重複させない
- FR-004: THE SYSTEM SHALL タグの並び順を**追加順**とし、作品ごとに保持する
  （表示の安定のため。並び替え操作は提供しない）
- FR-005: THE SYSTEM SHALL タグの読み書きを `MangaRepository` に閉じ込め、
  UI から直接 Firestore を読み書きしない
- FR-006: THE SYSTEM SHALL タグの追加・削除を**配列への差分操作**として行い、
  配列全体の上書きで他端末の同時変更を消さない
- FR-007: THE SYSTEM SHALL タグフィールドを持たない既存の作品ドキュメントを
  「タグ無し」として読み込み、エラーにしない（後方互換）
- FR-008: WHEN タグの保存に失敗した THE SYSTEM SHALL `logger.e` にエラー詳細を残す

---

## 非機能要件 (Non-Functional Requirements)

- NFR-001: パフォーマンス: 絞り込みの切り替えは追加の Firestore 読み取りを発生させず、
  既に購読済みの作品一覧をクライアント側でフィルタして 100ms 以内に再描画する
- NFR-002: オフライン挙動: 絞り込み・タグの追加削除いずれも Firestore キャッシュのみで動作すること
- NFR-003: 後方互換: 本機能を含まない旧クライアントが同じデータを読んでも壊れないこと
  （タグフィールドを知らない旧クライアントはそれを無視するだけで動く）
- NFR-004: 既存データの一括移行 (バックフィル) を必要としないこと

## 成功基準 (Success Criteria)

- SC-001: 連載3話分の作品に同じタグを付け、カンバンでそのタグを選ぶと
  3作品だけが各ステータス列に並ぶ
- SC-002: タグを入力し始めると既存タグが候補に出て、選択すると完全一致の名前が入る
- SC-003: 1 つの作品に複数のタグ（例: `連載:ヒーロー` と `商業`）を付け、
  どちらのタグで絞り込んでもその作品が表示される
- SC-004: 本機能のリリース前に作られた既存の作品が `タグなし` として一覧に表示され、
  タグを後から付けられる

---

## スコープ外 (Out of Scope)

- タグを独立したエンティティにすること（タグ ID / タグ専用ドキュメント / 色・説明などの属性）
- タグの一括リネーム・一括削除（あるタグが付いた全作品をまとめて変更する操作）
- 複数タグの同時選択による絞り込み（AND / OR 検索）
- タグ単位のメモ（キャラ設定・世界観などの共有メモ）
- タグが表すシリーズの中での話数・並び順の管理
- タグ単位の書き出し（複数作品をまとめて1ファイルに出す）
- 作品名・本文に対するフリーワード検索
- 絞り込み状態の永続化 / URL への反映

## 仮定 (Assumptions)

- ドメインモデル `Manga` の構造は [docs/design/data-model.md](../../../design/data-model.md) の現行定義に従う
- 作品一覧のカンバン (`MangaSelectPage`) とステータス3列の構成は現行のまま変えない
- 認証・権限制御は既存のまま。タグは利用者ごとに閉じており、他利用者と共有しない
- タグ名は日本語（全角）を含む任意の文字列。ファイル名等には使わないため禁止文字の考慮は不要
- 「シリーズ」は `連載:ヒーロー` のようなタグの付け方で表現する運用とし、
  システムがシリーズという概念を特別扱いすることはない
