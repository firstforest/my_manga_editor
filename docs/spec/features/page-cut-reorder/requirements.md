# Requirements: ページとカットの並べ替え

## メタデータ
- Status: implemented
- Owner: TBD
- Last Updated: 2026-11-01
- Related:
  - [design.md](./design.md) / [tasks.md](./tasks.md)
  - [docs/design/data-model.md](../../../design/data-model.md)（`MangaPage.sceneUnits` / `CloudMangaPage.pageIndex`）

## 概要

編集画面 (`/manga/:mangaId`) のページリストで、**ドラッグによる並べ替えをカットに割り当て**、
ページの並べ替えは「︙」メニューとページ一覧表示（グリッド）で行うようにする。

ネームを練るときに頻繁に入れ替えるのはページよりもカット（セリフとト書きの組）であり、
カットの入れ替えをいちばん手早い操作（ドラッグ）でできるようにしたい。
カットはページの中だけでなく、**別のページへも**ドラッグで移せるようにする。
一方、編集画面のページリストはページ全体がドラッグ対象になっているため、
同じ場所でカットのドラッグを受け付けると操作が衝突する。
ページの入れ替えは頻度が低いので、メニューと一覧表示に移す。

## 現状（この spec の出発点）

| 対象 | 場所 | 並べ替え手段 |
|---|---|---|
| ページ | 編集画面のページリスト | ページカード全体をドラッグ（右端のハンドル） |
| ページ | ページ一覧表示（グリッド） | ページをドラッグ |
| カット | 編集画面のページリスト（デスクトップ幅） | 各カット右の「︙」メニューの「上へ移動」「下へ移動」 |
| カット | 編集画面のページリスト（モバイル幅） | なし（カットは PageView で 1 面ずつ表示） |

---

## ユーザーストーリー

### US-1: カットをドラッグで入れ替えたい (priority: P1)

As a 漫画家（ユーザー），
I want 編集画面でカットをドラッグして同じページの好きな位置へ動かし，
so that コマ運びを試行錯誤するときに「︙」メニューを何度も開かずに済む。

#### Acceptance Criteria

- AC-1.1: THE SYSTEM SHALL 編集画面のページリスト（デスクトップ幅レイアウト）の各カットに
  ドラッグ用のハンドルを表示する
- AC-1.2: WHEN ユーザーがカットのハンドルをドラッグして同じページ内の別の位置で離した
  THE SYSTEM SHALL そのカットを離した位置へ移動し、他のカットの相対順序は保つ
- AC-1.3: WHILE カットをドラッグしている
  THE SYSTEM SHALL ドラッグ中のカットの見た目をポインタに追従させ、
  離したときに入る位置をカットの間の挿入線として表示する
- AC-1.4: WHEN カットが移動した
  THE SYSTEM SHALL そのカットのセリフ・ト書きの内容をカットと一緒に移動させる
  （内容が隣のカットと入れ替わって見えない）
- AC-1.5: IF ユーザーがドラッグを元の位置で離した、または挿入位置のない場所で離した
  THEN THE SYSTEM SHALL 並び順を変えず、保存処理も行わない
- AC-1.6: WHEN ユーザーがセリフ・ト書きの入力欄の中でドラッグした
  THE SYSTEM SHALL カットを移動せず、テキストの範囲選択として扱う
  （カットの移動はハンドルからのドラッグに限る）
- AC-1.7: THE SYSTEM SHALL 「︙」メニューの「上へ移動」「下へ移動」を引き続き提供する
  （ドラッグ以外で操作するための代替手段。対象は同じページ内）

#### Edge Cases
- カットが 1 つだけのページ → ハンドルは表示する（別のページへは移せるため）
- ドラッグ中にページ内のカット欄の上端・下端へ近づく → カット欄を自動スクロールする
- ドラッグ中に別端末で同じページのカットが追加・削除された → 離した時点の最新の並びに対して移動を適用する

### US-2: カットを別のページへドラッグで移したい (priority: P1)

As a 漫画家（ユーザー），
I want カットをドラッグして別のページのカットの間へ移し，
so that 「このコマは次のページに回す」といったページ割りの調整をコピー＆貼り付けなしでできる。

#### Acceptance Criteria

- AC-2.1: WHEN ユーザーがカットのハンドルをドラッグして別のページのカットの間（先頭・末尾を含む）で離した
  THE SYSTEM SHALL そのカットを元のページから取り除き、移動先のページの離した位置へ挿入する
- AC-2.2: WHILE カットをドラッグしている
  THE SYSTEM SHALL ポインタがページリストの上端・下端に近づいたらページリストを自動スクロールし、
  画面外のページへも運べるようにする
- AC-2.3: WHEN カットが別のページへ移動した
  THE SYSTEM SHALL 移動先のページで、そのカットのセリフが移動先のページ番号で「セリフをコピー」・
  ページ一覧表示・書き出しに含まれ、元のページからは含まれなくなる
- AC-2.4: THE SYSTEM SHALL カットの取り除きと挿入を 1 つの操作として保存し、
  途中で失敗しても「両方のページにある」「どちらのページにもない」状態を残さない
- AC-2.5: WHEN 元のページの最後の 1 カットを別のページへ移動した
  THE SYSTEM SHALL 移動と同時に元のページを削除し、後続ページのページ番号と L/R 表示を詰めて更新する
- AC-2.6: IF 元のページの最後の 1 カットを移動しようとしていて、そのページのメモ（「このページで描きたいこと」）が空でない
  THEN THE SYSTEM SHALL 移動前に「ページ N を削除します。このページのメモも削除されます」の確認ダイアログを表示し、
  キャンセルされたら移動しない
- AC-2.7: WHEN 移動先のページで移したカットを開いた（その後に元のページが削除された場合も含む）
  THE SYSTEM SHALL そのカットのセリフ・ト書きを失わずに表示し、編集・保存できる

#### Edge Cases
- 移動先がすぐ隣のページでも離れたページでも同じ振る舞い
- 元のページを削除したあとに、移動先のページを削除した → 移したカットのセリフ・ト書きも一緒に削除される
  （移したカットは移動先のページのものとして扱う）
- ドラッグ中に別端末で元のページまたは移動先のページが削除された → 移動しない（エラーは SnackBar で伝える）

### US-3: ページをメニューから入れ替えたい (priority: P1)

As a 漫画家（ユーザー），
I want 編集画面のページの「︙」メニューからページを前後に動かし，
so that ページリストのドラッグがなくなってもページ順を直せる。

#### Acceptance Criteria

- AC-3.1: THE SYSTEM SHALL 編集画面のページリストでページ全体をドラッグして並べ替える操作を提供しない
  （右端のドラッグハンドルを表示せず、その分の右余白もなくす）
- AC-3.2: THE SYSTEM SHALL 各ページのツールバーに「︙」メニューを置き、
  「前のページへ移動」「次のページへ移動」「ページを削除」を含める。
  「ページのセリフをコピー」はツールバーのアイコンのまま残す
- AC-3.3: THE SYSTEM SHALL ツールバーのゴミ箱アイコンを表示しない（削除は「︙」メニューからのみ行う）
- AC-3.4: WHEN ユーザーが「前のページへ移動」を選んだ
  THE SYSTEM SHALL そのページを 1 つ前のページと入れ替え、ページ番号と L/R 表示を更新する
  （「次のページへ移動」も同様）
- AC-3.5: IF そのページが先頭（末尾）である
  THEN THE SYSTEM SHALL 「前のページへ移動」（「次のページへ移動」）を無効表示にする
- AC-3.6: WHEN ページが移動した
  THE SYSTEM SHALL 移動後のページが画面内に見える位置までページリストをスクロールする
- AC-3.7: THE SYSTEM SHALL ページの「︙」メニューをデスクトップ幅・モバイル幅の両方のレイアウトに置く

#### Edge Cases
- ページが 1 つだけ → 「前へ」「次へ」はどちらも無効
- 連打したとき → 2 回目は 1 回目の結果が反映された並びに対して適用される（1 回目を巻き戻さない）

### US-4: ページ一覧表示でページを入れ替えたい (priority: P1)

As a 漫画家（ユーザー），
I want ページ一覧表示（グリッド）でページをドラッグして入れ替え，
so that 見開きの並びを見ながら遠くのページも一度で動かせる。

#### Acceptance Criteria

- AC-4.1: THE SYSTEM SHALL ページ一覧表示で、ページをドラッグして並べ替える操作を引き続き提供する
- AC-4.2: WHEN ページ一覧表示でページを並べ替えて編集画面へ戻った
  THE SYSTEM SHALL 編集画面のページリストに新しい並び順を反映している

## 機能要件 (Functional Requirements)

- FR-001: THE SYSTEM SHALL ページとカットの並び順を、他端末にも Firestore の snapshot 経由で反映する
- FR-002: IF 並べ替えの保存に失敗した
  THEN THE SYSTEM SHALL 表示を保存済みの並び順に戻し、SnackBar で失敗を伝える
- FR-003: THE SYSTEM SHALL カットの移動（ページをまたぐ場合を含む）でセリフ・ト書きの内容を作り直さず、そのまま引き継ぐ

## 非機能要件 (Non-Functional Requirements)

- NFR-001: パフォーマンス: カットをドロップしてから新しい並びが表示されるまで 300ms 以内
  （保存完了を待たず、ローカルキャッシュで先に反映する）
- NFR-002: オフライン挙動: オフライン中もカット・ページの並べ替え（ページをまたぐ移動を含む）ができ、再接続時に同期される
- NFR-003: アクセシビリティ: 同じページ内のカットとページの並べ替えは、ドラッグ以外の手段（「︙」メニュー）でも完結する

## 成功基準 (Success Criteria)

- SC-001: 1 ページ内のカットの 1 番目を 4 番目へ移す操作が、メニューを開かずに 1 回のドラッグで完了する
- SC-002: ページ 3 の最後のカットをページ 4 の先頭へ 1 回のドラッグで移せ、移したセリフがページ 4 の「セリフをコピー」に含まれる
- SC-003: 編集画面でページのカード内をどこでドラッグしても、ページが動いてしまうことがない
- SC-004: ページの並べ替えは「︙」メニューかページ一覧表示のどちらかで完結する

## スコープ外 (Out of Scope)

- モバイル幅レイアウト（カットを PageView で 1 面ずつ表示する画面）でのカットのドラッグ・移動。
  モバイル幅には現状カットの「︙」メニューもないため、別 spec で扱う
- 「︙」メニューからカットを別のページへ移す操作（ページをまたぐ移動はドラッグのみ）
- 番号を指定してページを任意の位置へ移すメニュー（遠くへの移動はページ一覧表示で行う）
- 編集画面のページの「︙」メニューにページ一覧表示への入口を置くこと（AppBar のグリッドアイコンを使う）
- 複数のカット・ページをまとめて選択して動かす操作
- 並べ替えの取り消し（Undo）

## 仮定 (Assumptions)

- ページの並びは `CloudMangaPage.pageIndex`、カットの並びは `CloudMangaPage.sceneUnits` の配列順で表す現行構造
  （[data-model.md](../../../design/data-model.md)）
- ページには常にカットが 1 つ以上ある（既存ルール）。そのためカットのないページへのドロップは考えない
- ページ一覧表示（`/manga/:mangaId/grid`）はドラッグでの並べ替えを持っており、この spec では挙動を変えない
